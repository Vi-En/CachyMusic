# Privacy, security and licensing release gate (3.0.0-dev.7.0)

## Local-first boundary

No developer telemetry, usage analytics, remote crash report, advertising, fingerprinting or remote font loading. Local settings, audio, covers, lyrics, queues and diagnostics stay local unless the user chooses an approved network operation. A hosted PWA necessarily contacts its host for installation/updates; use packaged assets for the strictest boundary. Browser and OS behavior outside the application is not controlled by this app.

* Soulseek: explicit connection; disclose IP/account/search/peer information and sharing choices. No anonymous or encrypted-transport claim. The native protocol and third-party client still need a complete audit. The updated code defaults new sharing to empty and allows explicit clearing; existing preferences may remain and must be reviewed. Android and desktop passwords are session-only. The PHP adapter no longer decrypts or persists prior encrypted password entries; subsequent account writes clear them. Historical backups may retain old entries and are not securely erased. Re-enter credentials after restarting. Android uploads are not implemented; desktop upload serving still needs implementation/verification. Only download/share authorized material.
* Metadata: explicit per-operation consent. MusicBrainz receives user-selected title, artist and album (not audio, paths or library); Cover Art Archive receives the selected release ID and may redirect to Internet Archive; LRCLIB receives the search fields. Each gets IP address and ordinary HTTP client information. No cookies/authorization/referrer are intentionally sent. No background online lookup. Response caps, timeouts and origin checks are in the client. Browser/WebView CORS, provider availability and usage conditions still need live validation. Do not bypass CORS using an untrusted proxy. No audio fingerprinting implemented.
* Artwork and lyrics: availability is not permission to redistribute or embed copyrighted works. Users must have applicable rights; provider terms and licensing must be reviewed before release, including MusicBrainz API identification and rate requirements, Cover Art Archive/Internet Archive and LRCLIB's lyric rights. No provider artwork/lyrics are bundled with CachyMusic. Do not market the app as providing unrestricted copyrighted content. General references: https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting ; https://musicbrainz.org/doc/About/Data_License ; https://musicbrainz.org/doc/Cover_Art_Archive/API ; https://lrclib.net/docs .

## Security changes and limitations

Inline scripts/event handlers were removed from the inspected HTML and track renderer; script CSP now only permits local scripts (styles still permit inline declarations). Browser provider connections are domain-allowlisted, with Internet Archive subdomains permitted for artwork redirects. Android allows selected provider subresource GETs while blocking remote main-frame navigation. The PHP CLI router rejects non-loopback requests, suspicious Host/Origin/Sec-Fetch-Site and can require a per-launch token. The desktop Node adapter rejects browser CORS, requires a local adapter header and packaged secret. Legacy server direct deployment is unsupported. Local processes running as the same OS user are outside the full adversary model; the current code is not an OS-level sandbox for every native parser.

Tag writing uses a dependency-free FLAC metadata parser and does not re-encode audio. PHP verifies the copied encoded-audio hash and replacement status; failure leaves the original when rename has not occurred. Supported replacement depends on filesystem permissions/atomic rename semantics. The writer rejects unsupported leading tags and malformed/oversized metadata. The browser and desktop now also offer conservative MP3 ID3v2.3/v2.4 tagged copies and explicit desktop in-place replacement, preserving the encoded payload in tested fixtures; unsupported tag structures are rejected. Standard WAV/AIFF are also supported for embedded ID3; non-ID3 chunks are preserved. Other formats remain library-only for now instead of unsafe legacy shell-based writes. Native Android writes are not enabled. Further fuzzing, file-system race tests, format compatibility, backup/undo, malicious artwork decoder isolation and validation of existing imported embedded art are required.

Soulseek updates partially bound decompression, packet strings, transfer size, names and destinations; avoid normal overwrite on completion and prevent some malformed requests. Full peer connection caps, bandwidth/backpressure, symlink-race defenses, parser fuzzing, protocol authentication and upload/sharing implementation verification are not complete. Do not promise immunity from attacks.

## Licensing

CachyMusic retains GPL-3.0-or-later (see LICENSE). As of dev.6.55 the previously bundled NMS Futura-derived font and its extracted notice are removed from the distributed kit. The upstream community project labels its font SIL OFL 1.1, but describes its relationship to a game-derived Futura typeface; the complete chain of rights for the exact binary was not established. See https://font.nmscd.com/ and https://nmscd.com/ . The application now uses locally installed geometric or system fonts. No remote font loading, font redistribution or claim that the earlier binary was unlawful. This deliberately removes a provenance dependency rather than relying on the embedded notice alone.

Release gates: pin and verify exact dependency versions, record provenance/checksums/SBOM, review every native codec and runtime component (including FFmpeg configuration, Electron, AndroidX and slsk-client), include license notices and complete corresponding source wherever required, validate update signing, run offline and network-capture tests, audit all upload/sharing behavior and device permissions, and perform independent security review. Do not distribute copyrighted music or covers with the app. This is engineering/legal risk reduction, not legal advice or a lawsuit-proof guarantee.

Original-file tag writes are explicitly opt-in. The new PCM range reader only accepts indexed same-origin loopback or Android app-asset media endpoints, exact byte-range responses and no redirects; it does not add any online provider or telemetry. Android API 24–32 media command broadcasts require an application signature permission; API 33+ also uses a nonexported receiver. Native build and security testing remain required.
