# CachyMusic dev.6.58 — Closed-beta acceptance

## Release scope

This is a source/build-kit candidate, not a compiled or signed release. The intended first cohort is voluntary local-library testing on a backed-up, disposable or fresh profile. Standard media playback, playlists, local settings and the existing interface are in scope. Android APK, background native playback, optional MySQL and live Soulseek are separate compatibility tracks; do not advertise them as validated until their gates pass. Experimental direct Android PCM remains developer-only. Do not offer the build to a tester experiencing severe distortion until that device passes the physical check below.

## Automated gates

From a clean extracted source tree on Linux, with the existing test dependencies installed (Node 22, PHP 8.1+, Python 3, Java 17, FFmpeg/FLAC, Chromium and the Python dependencies in `.github/workflows/browser-verification.yml`):

```sh
python3 tests/beta-acceptance.py --chromium /usr/bin/chromium --endurance --previous-kit /path/to/verified-previous-source.zip --previous-sha256 EXPECTED_SHA256 --output ../beta-acceptance-results
```

Add `--android` only when Gradle 8.2 and Android SDK 34/build tools are installed. Use the existing Windows and Arch CI workflows for target platform installation checks. The runner does not install dependencies, use a real music library, run live network peers, or upload logs. Keep the output outside the source tree and do not commit it. It runs source regression, actual browser waveform and playback fixtures, interaction/layout/accessibility checks, real-origin history and playlist IndexedDB, AudioWorklet, PWA, and optionally the two endurance and native build suites. `acceptance.json` records status, exit code, elapsed time and a source fingerprint before and after testing. Exit 0 means required automated checks completed; manual acceptance is still required. A navigation-policy block, timeout, omitted endurance or missing executable is not a pass. Run on a permitted local origin; do not disable managed browser security policies.

## Manual release checklist

Record the version and archive SHA-256, target OS/browser or WebView, test date and outcome. Record failures without personal music paths, account credentials or user databases. Every item in the declared beta scope must pass; otherwise narrow the scope or hold the release.

| Gate | Procedure | Stop/hold condition |
|---|---|---|
| Physical audio | Fresh profile; low physical listening volume; known-good WAV/FLAC/MP3; effects off, speed 1x; compare same device with a reference player | Severe distortion, unexpected gain, clicks or playback corruption |
| Upgrade and rollback | Back up closed old profile and backend; launch same origin with new kit; verify settings, playlists and library; restore backup into separate profile to prove rollback | Silent deletion, incorrect migration, database corruption or inability to recover |
| Local playback | Import Unicode paths; play, pause, seek, next/previous, repeat, queue and playlist navigation; close/reopen; test device disconnect | Playback escapes playlist, wrong track, stuck playback or loss of settings |
| Storage | Real browser transactions; concurrent tabs; history opt-out and clear; verify records remain correct after reopening | Stale records return, duplicate count, history created after confirmed opt-out |
| Offline/PWA | Install; offline restart and update; check assets, saved local music and service-worker lifecycle | Stale assets, failed startup or lost data |
| Accessibility | Keyboard and visible focus, 200% text, touch and screen reader, reduced motion; all relevant workspaces | Inaccessible primary control or modal trap |
| Endurance | Both browser widths beyond the 512-entry playlist history cap; actual device use at least two hours | Reproducible increasing retained resources, audio underruns, severe UI stalls or thermal issues |
| Native Android (only if offered) | APK build/lint, actual installation; screen-off playback, auto-advance, notifications, speed, Back, journal import and privacy clear; process restart | Crash, double/lost history outside documented handoff limitation, audio distortion or failure of privacy controls |
| Soulseek/MySQL (only if offered) | Disposable account/data, genuine search/download/cancel/retry, database migration and concurrent edits | Wrong transfer, unexpected file overwrite, connection/security or persistence failure |

## Known limitations

History recording identities are source/fingerprint based, not audio-content hashes. Legacy ID-only receipts cannot detect conflicting payloads retrospectively. The native outbox remains bounded at 1,024 receipts; malformed or failed receipts are retained and fairly rotated, not silently discarded. Native handoff may undercount an already-started recording. Actual Android storage and power behavior require device testing. Device-specific distortion is still an open release gate, irrespective of passing in-browser waveforms.

Keep beta distribution small, avoid production promises, and maintain a reversible update path. No public promotion until the declared platform scope has verified results.

Test the physical audio kit on the affected device before enabling optional processing or distributing the build. No automatic diagnostic certifies a DAC or speaker.

## Optional peer dependency gate

The local-only scope does not certify Soulseek. On a connected maintainer machine, resolve the exact package.json with `npm install --package-lock-only --ignore-scripts --no-audit --no-fund` against the public registry, review the entire lock, and run `python3 tests/dependency-audit.py /path/to/package-lock.json`. Use `--peer-lock /path/to/package-lock.json` with the beta acceptance runner to include this gate. The runner checks root identity, exact direct versions, registry and SHA-512 integrity entries, then audits high/critical advisories without installing packages. A registry error, incomplete response or rejected lock is not a pass. This does not authenticate separately supplied binaries, establish package license compatibility or certify live peer transfers. Use the reviewed lock with `npm ci --ignore-scripts` only after review; no automatic dependency upgrades are performed.

The portable stage accepts `--core-only` without Node or Soulseek. Even in the full portable edition, optional peer startup/exit cannot terminate the core shell. Actual Electron builds and target OS acceptance remain required.

### Backend upgrade and Debian package qualification

The acceptance runner now requires `--previous-kit` pointing to a verified prior source archive and `--previous-sha256` with its independently obtained SHA-256. Do not derive trust from an untrusted archive itself. The runner rejects optimized Python because tests rely on assertions. The disposable Linux backend test uses the old launcher, indexes an audio fixture, creates a playlist, stops the service, backs up the data, upgrades on the same origin, checks revision conflict handling, and restores the old backend from an isolated backup. This does not migrate a real browser profile. Add `--debian` for actual `.deb` assembly, extraction and backend startup. A package artifact is not a verified OS installation.

Android incremental ranges require an identity token derived from a regular, seekable provider descriptor. Unverifiable providers fall back through the existing normal media route or report a playback failure; they are not assumed to be safe incremental sources. FLAC picture masking uses a validated metadata chain and descriptor version; physical decoder acceptance remains mandatory.

## Local storage integrity
The source regression includes `tests/storage-integrity.py`, which exercises actual disposable PHP JSON stores, lock contention, duplicate recording paths, nested and conflicting batches, and scan API responses. These checks do not certify power-loss durability, MySQL/SQLite mirror consistency, real browser storage, or live peer services.

### Local artwork and crash-window acceptance

Run `python3 tests/artwork-commit.py` on a supported PHP 8.1+ host. User-edited artwork now lives in per-track `artwork-*` directories alongside `library.json` in the data directory, not in the cover cache. Back up and restore the entire data directory with the backend stopped. Do not delete these directories during cache cleanup. A staged but unreferenced object is not served; no automatic garbage collection or migration of older cache-only artwork is performed. File contents are synchronized before rename; directory synchronization is best effort and physical power-loss durability is not certified. Original media tag edits and optional SQL updates are separate operations.

### Render-clock and contention qualification (dev.6.61)

Run `python3 tests/default-audio-browser.py` in isolation, then with `--suspend-probe`, then with `--load-workers 4 --main-thread-busy-ms 25`. The test records the legacy 350 ms wall-clock window and two independent windows after bounded render-clock and media-clock advancement. A non-probe legacy failure remains a failure even if later windows recover; the deliberate suspension case must demonstrate a stale legacy window and then recover. The waveform tolerances are unchanged. These are sampled application-graph measurements, not continuous loopback or physical transducer acceptance. Run separately from other qualification jobs, except for the explicitly generated workload. Never use a successful retest to erase an earlier intermittent failure.

Local indexing now has one in-flight worker job and an explicit owner; cancelled/superseded pre-commit imports discard provisional tracks. An asynchronous worker failure stops that import rather than rerunning costly work on the main thread. A platform unable to create a worker initially can still use serial compatibility parsing. The controlled-worker browser fixture is not a genuine-origin Worker acceptance test. `tests/storage-crash-recovery.py` exercises real POSIX process kills around JSON publication and verifies subsequent writes; it is not a physical power-failure test. Abandoned temporary objects are not automatically deleted.


### Local profile maintenance (dev.6.63)

Stop all application processes and back up the complete persistent data directory. From the source root, run `php bin/cachymusic-storage-audit.php --data-dir /absolute/profile/path` to inspect the existing JSON profile. This does not initialize, migrate or overwrite the profile. It counts aged root write stages, reports missing or hash-mismatched committed artwork and unreferenced artwork, and refuses an unsafe or locked library. It is not a general filesystem scanner.

With the application fully stopped, add `--quarantine-abandoned` to move eligible root `.cm-write-*` regular single-link files at least 24 hours old (mtime) into a unique private quarantine directory in the same profile. No files are deleted, no automatic restore is attempted, and no artwork objects or artwork staging files are moved. Check the report and retain the quarantine with your backup. Temporary filename patterns differ across platforms; unknown names are left untouched. Linux exercised; Windows filesystem semantics require owner acceptance. Do not use this command for live SQL recovery.

Cover requests now resolve the current track and authorized canonical source before consulting the disposable source-bound cache; old `tid_*` aliases are ignored. Cache identity includes file stat and recognized folder-cover stat data, not full audio hashes. JPEG/PNG header and allocation bounds are enforced; other embedded formats may fall back to default art. A private, disposable 64-bucket index under `cover-index-v1/` in the JSON data directory avoids repeated full-library parsing on normal POSIX warm requests. Each bucket is checksummed and tied to the authoritative library file's device/inode/size/mtime/ctime; changed or corrupt entries fall back to the full snapshot. This assumes ordinary atomic library commits, not adversarial same-user modification or in-place timestamp-preserving edits. Windows and MySQL use full reads. The index contains only recording paths, artwork references and authorized directory paths, not credentials. With all backends stopped, the disposable index directory may be removed to rebuild it; do not remove `artwork-*` or the library. Validate cold and warm loading performance on a large physical library and verify edited artwork, folder cover replacement, and thumbnail refresh.

### dev.6.63 backend and source release boundaries

- Explicit server directory changes and the native folder picker use POST. Browser-selected files are imported directly rather than guessing a server path from a folder basename. Use the native picker or enter an explicit server path for server-indexed libraries. Refresh the app shell after upgrade; old MPRIS clients cannot consume the acknowledged command queue.
- Media and artwork lookups share the private generation-bound projection on local POSIX profiles; SQL and Windows fallback performance remains unqualified. Subprocess deadlines and captured-output limits are per direct process. Temporary-output file growth is sampled, not a hard disk quota; child trees and stalled OS I/O are not guaranteed bounded.
- For offline disposable cover-cache inspection, stop all backends and run `php bin/cachymusic-cover-cache.php --cache-dir PATH`. After backing up the complete profile, optionally add `--prune-to-bytes 536870912` to prune recognized generated cache entries older than seven days toward 512 MiB. Fresh entries, legacy ID caches, authoritative artwork, unknown entries, symlinks and hardlinks are not deleted. Exit 3 means the target could not be met safely. This is not automatic cache eviction.
- To rebuild a clean normalized source ZIP, run `python3 tools/build-source-kit.py /outside/checkout/CachyMusic-3.0.0-dev.7.0-cross-platform-build-kit.zip`. Two builds with the same source and Python/zlib implementation must match byte-for-byte. The tool refuses to overwrite existing artifacts. This does not sign packages or establish reproducibility of external runtime binaries.

### dev.6.64 bounded scans and desktop command qualification

- Local JSON scans publish a directory change and its indexed rows together only after successful traversal and response validation. Limits are backend environment variables: `CACHYMUSIC_SCAN_SECONDS` (default 300, range 1–3600), `CACHYMUSIC_SCAN_ENTRIES` (250,000, range 1–1,000,000), `CACHYMUSIC_SCAN_TRACKS` (25,000, range 1–25,000), `CACHYMUSIC_SCAN_BYTES` (32 MiB, range 1 KiB–64 MiB). A budget failure leaves the prior local JSON intact; select a smaller directory or adjust the backend configuration. Managed scans can reuse validated metadata checkpoints; unmanaged scans cannot. The deadline is cooperative and cannot preempt stalled filesystem, database or OS calls; PHP disconnect detection is best-effort. Since dev.6.70 SQL scans use a separate authoritative InnoDB transaction, with no JSON mirror publication. Test large uncached libraries on the actual target machine before release.
- MPRIS uses a 64-entry FIFO with client claims (15 seconds), acknowledgement receipts (last 256), and queued command expiry (60 seconds). Acknowledgement means dispatched to the browser action, not completed playback. Lost acknowledgements are retried without executing the action again. An expired claim is recorded as uncertain and is never automatically replayed. `GET php/api/mpris_state.php?action=command_status` reports pending count and recent outcomes. A legacy mailbox is flagged but not replayed; reload the browser and restart the desktop bridge after upgrade. Commands sent while no player is active may expire. Sender errors are reported to D-Bus; do not blindly retry ambiguous non-idempotent actions.
- POSIX subprocess stdout/stderr use capped nonblocking pipes, not output spool files. On Linux with POSIX PHP and `/usr/bin/setsid`, a verified live child process group can be terminated on failure. This is not a sandbox, hard filesystem quota or guarantee for children that detach/escape or outlive an already-exited group leader. Windows retains the previous sampled temporary-spool fallback. Test actual mixer, artwork, ffprobe and file-tag rewriting on target platforms.

### dev.6.66 managed scan isolation and cache admission
The managed desktop launcher (source and portable Electron) owns a separate, lower-CPU-priority PHP worker where supported. New clients submit a bounded scan job, poll its state, and fetch a result only after publication. Cancel before the commit boundary to preserve the previous JSON library. If publication has started or a worker disappears, refresh the server library rather than automatically replaying an uncertain operation. One active job and one terminal result are retained per profile. Restart the backend if the worker is unavailable; do not start a detached worker manually. Unmanaged PHP and explicitly enabled SQL retain the legacy synchronous route. Since dev.6.70 managed legacy direct scan routes reject the request; reload after upgrading.

Interrupted managed scans retain a disposable, private metadata journal of at most 16 MiB for one root. A retry re-traverses the directory and verifies the source and sidecar stat identity before reusing a completed metadata record; no provisional track IDs are reused. A successful scan removes the journal. A stat-preserving file mutation can evade this cache. The journal is not a backup or a guarantee of power-loss durability. Existing local JSON commit conflict detection remains authoritative.

Recognized disposable artwork cache admissions are serialized, with defaults of 256 MiB and 8,192 entries (`CACHYMUSIC_COVER_CACHE_BYTES`, `CACHYMUSIC_COVER_CACHE_ENTRIES`; zero disables new cache writes). Oldest-write recognized derivatives may be evicted. Unknown/legacy files, links and authoritative edited artwork are never evicted by admission control. Busy or over-expensive inventory skips caching. Existing oversized caches and atomic staging bytes are not subject to a hard disk quota. The idle worker warms missing POSIX lookup buckets from one stable library generation; stale or interrupted warming falls back to the authoritative lookup. Windows and SQL warming are not enabled.

Run `python3 tests/async-scan.py`, `node tests/server-scan-client.mjs`, `python3 tests/cover-index.py` and `python3 tests/cover-cache-admission.py`. On actual devices, start music, refresh the same directory, cancel during slow indexing, retry, check unchanged recording identity and continuous sound, then test a deliberate root change while stopped. Test Windows worker startup/stop and the portable desktop runtime separately. These tests are not hardware audio acceptance.

### dev.6.66 managed library transition
On a managed desktop, play a track, open the folder dialog, and cancel it. Audio should remain uninterrupted; the saved directory must not change. Select a different root, stop playback before confirming the replacement, and verify that failed/cancelled scans retain the prior root. If publication is uncertain, reload the client before resuming. Test two tabs and stale root confirmation separately; the client guard is tab-local. Revoked roots outside other authorized media directories must deny streaming, artwork and metadata access. Idle maintenance trims recognized disposable cover derivatives only; zero budget removes eligible derivatives, never authoritative artwork. SQL and unmanaged servers do not provide equivalent background isolation or transaction guarantees.

### Managed metadata edits (dev.6.67)
On a backed-up local desktop profile, verify library edits and artwork uploads through the managed worker. While playing a different recording, write tags to a disposable supported audio file and confirm exact audio continuity. Stop playback of the target before writing its file. A busy worker rejects new edits, and an uncertain edit requires refreshing the library and checking original tags before retrying. No cross-client playback lock or atomic transaction across the original file and the library is provided. Linked `library.json` or lock aliases are no longer supported; use an actual profile directory. Unmanaged local JSON retains synchronous metadata compatibility. SQL beta metadata is limited to SQL-native text fields (see below).

### dev.6.68 additional acceptance boundaries
- Reload controlled browser clients after upgrade. With a managed local JSON desktop profile, request uncached artwork while playing a different recording. Since dev.6.70 all managed requests defer cold extraction. Unmanaged servers retain the synchronous compatibility route. Check artwork eventually appears, cancellation and revoked directory access, and audio continuity. A saturated/unavailable queue may show default art; a fresh request can retry. No private artwork responses are added to CacheStorage.
- Stop playback of the target recording in every client before original-file tag editing. Shared/exclusive recording locks protect active HTTP transfers within a profile, not an entire listening session or external writers. An overlapping edit or range request may be refused. Original file and library record are separate transactions.
- Back up the complete profile before upgrade. Local library reads/writes are bounded by CACHYMUSIC_LIBRARY_MAX_BYTES (default 64 MiB); existing oversize data is refused, never truncated. Authoritative artwork admission is bounded by CACHYMUSIC_ARTWORK_STORE_BYTES (default 1 GiB) and CACHYMUSIC_ARTWORK_STORE_ENTRIES (default 8192); no authoritative artwork is automatically deleted. These are not whole-profile disk quotas.
- On Windows source launch, verify the Python supervisor probe succeeds and exercise child timeout, output overflow and shutdown with sacrificial fixtures. Windows Job Object behavior requires actual Windows acceptance. Portable Windows and failed probe paths retain sampled spool limits. Windows lookup projections retain the conservative full-read fallback.
- SQL statement contracts are tested without a live SQL service. Do not claim SQL/JSON atomicity or migrate a production SQL profile without backup and real integration qualification. Dependency registry resolution and publisher signing remain separate release gates.

### dev.6.70 engineering boundaries
- Hard-linked recordings are rejected by scan, stream, artwork and metadata policies; use ordinary single-link files.
- With all backends stopped, the storage audit reports bounded apparent single-link file bytes and counts; this is not allocated disk usage or a whole-profile quota.

### Cooperative desktop recording reservations

Open the managed local JSON application in two independent browser clients on the same profile. Play an indexed server recording in one, then attempt an original-file edit of that recording from the other. With a confirmed reservation, the edit must be refused before library or audio bytes change. Ordinary library-only edits remain available. Pause the first client, then retry the original-file edit with a disposable copy of the recording. If a client crashes, a reservation expires after 90 seconds without renewal. Background browser throttling, offline clients, unmodified legacy clients, and a prebuffered successor may leave gaps in coverage. This is cooperative protection for original-file editing, not global session exclusivity or a guarantee against root replacement. A failed renewal deliberately does not stop playback.

## dev.6.72 local authority coordination

- In a local JSON profile, directory changes (including peer shared/download directory changes) are refused while any confirmed recording reservation remains active. Same-root scans and ordinary metadata-only edits remain available. Pause all clients and retry after release; an abandoned lease may take 90 seconds to expire. A corrupt reservation journal blocks root changes and original-file edits; preserve it for offline recovery. A failed scan publication leaves the previous library intact. This is cooperative protection, not exclusive or universal playback ownership.
- The Windows Python source launcher requires a successful bounded subprocess-supervisor probe. If the probe fails, core playback can continue, but external PHP tool calls (including FFmpeg-based metadata or artwork operations) are refused rather than falling back to unbounded child disk output. The portable/unmanaged Windows route still has its sampled compatibility fallback. Verify actual Windows Job Object operation on the target system. Windows lookup continues to use authoritative full reads.

## dev.6.73 aggregate authoritative-write admission

The local profile can optionally configure `CACHYMUSIC_PROFILE_MAX_BYTES` (apparent bytes) and/or `CACHYMUSIC_PROFILE_MAX_FILES` (maximum 100,000). Set them consistently for every writer before starting the backend. Unset means the prior per-component limits remain in effect. When enabled, JSON library and immutable artwork publication share a nonblocking admission lock and count all regular profile files, including the old target, abandoned stages and unknown data, plus the new staging file. Incomplete inventories (150 ms cooperative deadline, 100,000 entries, depth 32), aliases, invalid limits and contention refuse the write; no automatic data deletion. On a populated profile, leave room for both the old and new library and normal operating files. Read-only playback and bounded command/lease/recovery journals remain independent of admission. Those journals, SQL, external writers, downloads, separate cache roots, filesystem allocation and concurrent uncoordinated changes mean this is not a hard global filesystem quota. Windows filesystem/junction semantics are not qualified. A failed artwork-reference commit may retain an unreferenced immutable object; preserve it for inspection. Use `bin/cachymusic-storage-audit.php` with the backend stopped to inspect usage.

## dev.6.74 Windows content-bound lookup and portable tool policy

Managed Windows launchers generate a fresh, dedicated lookup key at startup. With PHP sodium available, the derived lookup uses an authenticated encrypted bucket bound to a SHA-256 digest of the exact bounded `library.json` bytes. The authoritative file is still read and hashed on every request; only full JSON decoding is avoided on a hit. The cache is disposable (`lookup-encrypted-v1` under the cache root), contains no credentials, and is not portable between launcher sessions. No key is stored in the profile. Missing crypto, missing key, malformed cache or unsafe cache path falls back to authoritative reads. This is not a filesystem/ACL certification, and untrusted processes running as the same user are outside this threat model. POSIX inode-based indexing is unchanged.

Portable Windows distributions may supply an independently reviewed `runtime/python/python.exe` and all its supporting files in the existing runtime manifest. The staged supervisor must complete its Job Object probe before external PHP tools are enabled. Missing or failed probes disable these tools (including some artwork, metadata and tag editing operations), not core playback. No Python download or implicit use of system Python occurs. Unmanaged PHP deployments retain compatibility behavior; they are not a fully isolated production profile. On Windows, enable the PHP sodium extension for the encrypted lookup and test cold and warm stream/cover latency, revoked roots, same-size file replacements, restart/key rotation, and cache denial. Actual native Windows execution, not just the portable contract fixture, is required.
